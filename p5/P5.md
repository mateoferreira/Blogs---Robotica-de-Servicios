# ALGORITMO DE AUTOLOCALIZACION CON MONTECARLO BASADO EN LASER

En esta práctica he tenido que implementar el algoritmo AMCL para la autolocalización de una aspiradora, cuyo sensor principal para autolocalización es el láser, y vamos a contar con odometría en las ruedas para medir la distancia recorrida entre iteraciones, para poder implementar este algoritmo


## Teoría

La teoría la he sacado directamente de los apuntes de la asignatura robótica móvil.

Este algoritmo no es discretizado, es decir, no tenemos un mapa de celdillas como estamos acostumbrados. En vez de miles de celdillas tenemos cientos de partículas (x, y, theta), lo que permite una buena escalabilidad y reducir el coste computacional. 
Tenemos tres ingredientes: 

- Modelo probabilístico de observación sensorial: medidas del láser en cada iteración
- Modelo probabilístico de movimiento: Si nos movemos un metro, desplazamos cada partícula en una gausiana, para no contar con un desplazamiento perfecto, sino tener en cuenta el ruido de los sensores de odometría
- Población de partículas: cada una tiene un peso. Este se muestra con un color normalizado en pantalla (entre 1 y 0.5, porque descubrí que los valores muy bajos de peso no se distinguían bien)

La probabilidad de una partícula se mide por la observacion teorica. Si el robot estuviera en x y posicion con theta orientación, a partir del mapa, te deberia de dar una cierta lectura del laser. Pero puede haber sitios donde te de la misma lectura. Hay que hacer una observacion teorica por cada x, y y la comparamos con la obtenida por el láser en t. Para tener en cuenta el ángulo, giro la observación real 4 veces a ver si alguna coincide con la observación teórica (intenté girarla mas veces, pero me iba un poco peor al tener más coste). Si la observacion teorica en cierta posicion es muy distinta  a la que leen los sensores, sabemos que no estamos en esa partícula, es decir, su probabilidad va a ser muy baja.

Para hallar la similitud, por cada rayo, los comparamos con el observable, y miramos si es similar. Para hallar la similitud entre la obs real - la teorica en t: *e^ -(abs(obs_real-obs_teorica))* Si la distancia es 0, la probabilidad de estar en esa posicion, es 1. Si la distancia es infinita, es 0. Esto se hace para una posicion. Hay que hacerlo por cada posicion. Esto da mucha simetria entre posiciones, pero como la probabilidad se acumula, vamos descartando.

En cada iteración actualizamos es el peso de cada partícula, para ello, en cada iteración usamos el algoritmo de la ruleta para sacar las particulas en t+1:
Hacemos una grafica circular donde cada sector es la aportacion de cada particula. La grafica es la suma de probabilidades. Si tenemos 100 particulas, tiramos 100 veces la ruleta, y en la siguiente iteracion, las particulas van a ser hijas de las mas probables. 
Para que no sean copias exactas de los padres, le añadimos ruido termico. 
Las particulas inicialmente siguen una probabilidad uniforme (todas con el mismo peso).

Si todas las particulas tienen probabilidad muy bajas, o si todas salen en el mismo sitio con probabilidad baja, el algoritmo sabe que estamos muy perdidos, por eso se remuestrea, es decir, se vuelven a tirar otra evz por todo el mapa.

EL algoritmo es AMCL, es decir, adaptive montecarlo. Esto de adapted tiene que ver con el número de partículas. Cuando están todas basstante juntas, reducimos el número de partículas para reducir el coste computacional. Esto quiere decir que lo primero que vamos a tener que ajustar es el número máximo y mínimo de partículas.
